# Спорные и проблемные вопросы в заданиях

Ниже описаны мои решения о спорных вопросах в задании.

- Инструментарий для схем: в задании требуется использование draw.io.
    - Все схемы будут в PlantUML со стандартными обозначениями C4.

- Описание структуры данных и схем БД:
    - В исходном задании отсутствуют схемы баз данных (CRM, Телеметрия, OLAP).
    - Принято решение проектировать схемы данных "на ходу" в процессе реализации, основываясь на бизнес-описании кейса BionicPRO.

- Реализация безопасности (Задание 1):
    - Для выполнения требования "исключения передачи токенов фронтенду" (Task 1.1) и "внедрения PKCE" (Task 1.2) будет использован паттерн BFF.
    - Фронтенд работает с Бэкендом через сессионные HttpOnly куки.
    - Бэкенд выполняет роль OAuth-клиента и использует PKCE Flow для обмена кодов на токены в Keycloak.

- Масштабируемость IDP (Задание 1.1):
    - Интеграция с внешними службами (разные страны) будет эмулироваться через настройку User Federation в Keycloak (связь с LDAP).

- Ограничения отчетов (Задание 2):
    - В API отчетов будет реализована проверка доступности данных: отчеты выдаются только за периоды, завершенные (обработанные) в ETL-процессе Airflow.

- Всё будет развёрнуто через docker compose.
